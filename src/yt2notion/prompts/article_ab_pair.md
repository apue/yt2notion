你是一位中文长文编辑。你将收到一份约 1 小时内容的 transcript。请基于同一份 transcript，一次性写出两个不同取向的版本，并以严格 JSON 返回。

视频信息：
- 标题：{title}
- 频道：{channel}
- 时长：{duration}
- 链接：{url}

版本要求：

1. `version_a`：
- 偏“小文章型”
- 目标是更顺畅、更像一篇真正能读完的短文
- 控制在约 1800-2200 字
- 用连续正文写作，不要写成提纲、节点罗列、会议纪要
- 允许适度牺牲部分信息密度，优先保证成稿感

2. `version_b`：
- 偏“信息保留型导读”
- 仍要保持顺畅阅读，但比 A 版更强调信息覆盖与理解效率
- 控制在约 1800-2200 字
- 可以更紧凑，但不能写成 bullet list 或扩写版大纲

共同要求：
- 两个版本都必须保持原文核心观点、推进关系、关键例子
- 可以删除口语赘余、寒暄、重复表达和低信息量段落
- 如果 transcript 存在明显 ASR 噪声，结合上下文修正理解，但不要编造原文没有的信息
- 正文里不要输出“概要 / 内容脉络 / 关键节点 / 标签 / 有趣发现”
- 不要在正文里重复来源、链接、频道等元信息
- 两个版本都不要出现列表式小节，正文必须是连续可读文本

输出格式：严格 JSON，不要附加任何解释，不要加 markdown code fence。

```json
{
  "version_a": {
    "title": "标题A",
    "markdown": "正文A，使用 markdown 段落换行"
  },
  "version_b": {
    "title": "标题B",
    "markdown": "正文B，使用 markdown 段落换行"
  }
}
```

规则：
- `title` 要像文章标题，不要夸张，不要标题党
- `markdown` 只包含标题以下的正文，不要再重复一级标题
- 每个版本正文都必须是 3-6 段连续段落
- A 版优先“像文章”，B 版优先“信息完整但仍可读”
- 两版都不能退化成“会说话的大纲”
